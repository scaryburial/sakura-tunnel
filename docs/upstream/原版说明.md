# 樱隧 Sakura Tunnel

基于 [frp](https://github.com/fatedier/frp) 二次开发的内网穿透服务端，主打三件事：**多用户**、**限速/流量计费**、**给小白的一键接入**，外加一个**全中文樱花风控制台**。

服务端与客户端合并成 **一个二进制**（`sakura`），默认跑服务端，`sakura client` 跑客户端；服务端自己托管客户端二进制，对方一条 `curl | bash` 就能装好。

---

## 一、体积

同一份代码、同一台机器、`CGO_ENABLED=0 -trimpath -ldflags "-s -w"` 条件下实测：

| 产物 | 未压缩 | UPX `--best --lzma` |
|---|---|---|
| 上游 frp 服务端（含官方 Vue 面板） | ~20.3 MB | — |
| 上游 frp 客户端 | ~16.7 MB | — |
| **樱隧·服务端+客户端合体** | **20.8 MB** | **5.9 MB** |
| **樱隧·服务端+客户端合体（-upx 版）** | — | **≈5.9 MB（28%）** |

要点：**一个 5.9 MB 的文件同时是服务端和客户端**，上游要 37 MB 的两份。压缩后体积只有 28%。

> 已经做过但收益很小的裁剪：去掉 `k8s.io/apimachinery`（配置解析改用 `sigs.k8s.io/yaml`）≈ 50 KB。
> 想再往下压到 ~15 MB 未压缩 / ~4.4 MB UPX，需要裁掉 QUIC、KCP、虚拟网卡（wireguard tun）与 Prometheus，属于「功能换体积」，需要时按 `pkg/transport`、`client/connector.go`、`server/service.go` 里的监听器注册逐项摘。

## 二、跟上游 frp 的差异

| 能力 | 上游 frp | 樱隧 |
|---|---|---|
| 认证 | 全局一个 token | **多用户：每户独立 token + 到期时间** |
| 面板 | 英文 Vue，需 npm 构建 | **纯静态中文樱花风，无构建步骤，124 KB** |
| 限速 | 每 proxy，且由客户端自己声明 | **服务端按用户强制限速（客户端改不了）** |
| 流量 | 每 proxy 今日流量 | **按用户累计流量 + 今日流量 + 配额** |
| 配额 | 无 | **超额拒绝登录 / 拒绝新建隧道** |
| 隧道数限制 | 全局 `maxPortsPerClient` | **按用户 `maxProxies`** |
| 下发给客户 | 手写配置 | **`curl \| bash` 一键接入，自动装 systemd/计划任务** |
| 部署形态 | frps + frpc 两个包 | **一个二进制双角色** |

## 三、服务端部署

```bash
# 1. 上传 sakura-linux-amd64 与配置
mkdir -p /opt/sakura && cd /opt/sakura
cp sakura-linux-amd64 sakura && chmod +x sakura
cp server.toml .

# 2. 配置（见下方 server.toml）
vim server.toml

# 3. systemd
cat > /etc/systemd/system/sakura.service <<'EOF'
[Unit]
Description=Sakura Tunnel Server
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/sakura
ExecStart=/opt/sakura/sakura -c /opt/sakura/server.toml
Restart=always
RestartSec=3
LimitNOFILE=1048576

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload && systemctl enable --now sakura
```

`server.toml`：

```toml
bindPort = 7443                        # 客户端接入端口
webServer.addr = "0.0.0.0"
webServer.port = 7500                  # 面板端口
webServer.user = "admin"
webServer.password = "换成强密码"

auth.method = "user"                   # 多用户模式
auth.userFile = "./users.json"         # 用户库（自动创建）

transport.tls.force = true
allowPorts = [{ start = 6000, end = 6999 }]
```

访问 `http://服务器IP:7500/`，登录后：

1. **用户** → 新建 → 填最大隧道数、限速、配额、到期时间 → 得到 `sk_xxx` 密钥；
2. 点该用户的 **一键接入** → 复制 Linux / Windows / Docker 三种命令；
3. 把命令丢给对方，对方终端里粘贴回车即可，自动下载客户端、写配置、装成系统服务。

### 客户端分发文件

服务端会从 **运行目录下的 `clients/`** 提供下载：

```
/opt/sakura/
├── sakura
├── server.toml
├── users.json
└── clients/
    ├── sakura-linux-amd64
    ├── sakura-linux-arm64
    └── sakura-windows-amd64.exe
```

`/dl/<文件名>` 找不到时，如果请求的正好是服务端自己的平台，会把自身作为客户端下发。

## 四、多用户是怎么实现的

- **认证**：新增 `auth.method = "user"`。客户端配置 `user = "alice"` + `auth.token = "sk_xxx"`，服务端用 `users.json` 里该用户自己的 token 校验（常量时间比较）。
  - 每户 token 不同 ⇒ 无法共用一份共享密钥；链路机密性由 `transport.tls` 保证，所以控制通道的 token 加密层在这一模式下不启用。
- **限速**：登录时把用户的 `bandwidthLimitKbps` 换算成 bytes/s，随 `proxy.Options` 注入 `BaseProxy.limiter`，在 `server/proxy/proxy.go` 的 join 处同时限制上下行；取「用户限额」与「proxy 自己声明的限额」中更小的那个，客户端无法绕过。
- **流量**：`pkg/metrics/mem` 在 `AddTrafficIn/Out` 里通过 `UserTrafficHook` 回调把字节数记到用户账上；`userdb` 每 30 秒落盘一次（原子写，`users.json.tmp` → rename）。
- **配额/到期/隧道数**：登录时校验一遍（`VerifyLogin`），每次 `NewProxy` 再校验一遍（`control.go: handleNewProxy`），超限返回中文原因给客户端。

### API（面板用的就是这些，Basic 认证）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v2/system/info` | 版本、端口、总流量、用户数、运行时长 |
| GET | `/api/v2/users?q=` | 用户列表（含今日/累计流量、在线、限速、配额） |
| POST | `/api/v2/users` | 新建用户，返回一次性 token |
| PUT | `/api/v2/users/{user}` | 改限额/配额/到期/备注/启停 |
| DELETE | `/api/v2/users/{user}` | 删用户 |
| POST | `/api/v2/users/{user}/token` | 重置密钥 |
| POST | `/api/v2/users/{user}/traffic` | 清空累计流量 |
| GET | `/api/v2/users/{user}/install` | 三种一键接入命令 |
| GET | `/api/v2/proxies` | 隧道列表（含今日流量、连接数） |
| DELETE | `/api/v2/proxies` | 批量删隧道 |

响应统一信封：`{"code":200,"msg":"success","data":{...}}`，出错 HTTP 状态码同 `code`，`msg` 是中文原因。

## 五、一键接入做了什么

`GET /i/<token>`（Linux）返回一段自包含 bash 脚本：

1. 按 `uname -m` 选架构，从 `/dl/sakura-linux-<arch>` 下载客户端；
2. 生成 `client.toml`（服务器地址、端口、user、token、TLS）；
3. root 用户 → 装 systemd 服务并 `enable --now`；普通用户 → `nohup` 后台跑；
4. 打印转发规则（默认本机 `127.0.0.1:22` → 服务器 `6000`）。

支持参数：`... | bash -s -- --remote-port 6001 --local 127.0.0.1:8080 --dir /opt/sakura-client`

`GET /w/<token>`（Windows）返回 PowerShell 版：下载到 `%LOCALAPPDATA%\sakura`，注册计划任务开机自启，立即后台启动。

Docker：`docker run -d --network host ...`（用环境变量传参，需自备镜像）。

## 六、二次开发

```bash
# 依赖：Go 1.26+、git；Windows 上 UPX 4.2.4
git clone <this repo> && cd frp
pwsh -File build.ps1                 # 产出 dist/ 与 dist/clients/
pwsh -File build.ps1 -NoUPX          # 不压缩
```

代码地图（相对上游新增/改动）：

| 位置 | 作用 |
|---|---|
| `pkg/userdb/` | 用户库：CRUD、token、配额、流量记账、原子落盘 |
| `pkg/auth/userauth.go` | 多用户校验器（登录 / 心跳 / 工作连接） |
| `pkg/onetap/` | bash / PowerShell / docker 一键脚本生成 |
| `pkg/brand/` | 产品名（改版只改这里 + `pkg/webui/dist`） |
| `pkg/webui/` | 内嵌中文控制台（`dist/` 下三个文件，无构建） |
| `server/http/controller_users.go` | 用户与安装命令的 API |
| `server/public_router.go` | `/i` `/w` `/dl` 公开端点 |
| `server/control.go` | `checkUserPolicy`（配额/到期/隧道数）、`userBandwidthLimit` |
| `server/proxy/proxy.go` | 用户限速注入 |
| `cmd/sakura/` | 双角色入口（`sakura` = 服务端，`sakura client` = 客户端） |

改版清单（去指纹）：换 `clients/` 里的二进制名、换 `pkg/brand`、换面板 favicon/title、换 `transport.tls` 自签证书、改默认端口、`-trimpath` 去掉构建路径。

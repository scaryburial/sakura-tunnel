# 一键接入是怎么实现的

三个**免登录**端点（`server/public_router.go`，故意放在面板 Basic 认证之外，用路径里的 token 当密钥）：

| 路径 | 作用 |
|---|---|
| `GET /i/{token}` | 返回 Linux/macOS 用的 bash 安装脚本 |
| `GET /w/{token}` | 返回 Windows 用的 PowerShell 安装脚本 |
| `GET|HEAD /dl/{name}` | 下发客户端二进制 |

## /i 脚本干了什么

1. `uname -m` 选架构（amd64 / arm64 / armv7）；
2. 从 `/dl/sakura-linux-<arch>` 下载客户端到 `~/.sakura/sakura`（已存在则跳过）；
3. 用内嵌模板生成 `client.toml`（服务器地址、端口、user、token、TLS）；
4. root → 装 systemd 并 `enable --now`；普通用户 → `nohup` 后台跑；
5. 打印转发规则。

参数：

```bash
curl -fsSL http://host:7500/i/sk_xxx | bash -s -- \
  --remote-port 6001 \
  --local 127.0.0.1:8080 \
  --dir /opt/sakura-client
```

## /w 脚本干了什么

下载到 `%LOCALAPPDATA%\sakura\sakura.exe`，写 `client.toml`，注册计划任务（登录时启动）并立即后台运行。

## /dl 从哪拿文件

按顺序找：

1. `./clients/<name>`（相对服务端工作目录）
2. `<可执行文件目录>/clients/<name>`
3. 请求的正好是本机平台（`sakura-linux-amd64` 之于 linux/amd64）→ 直接下发服务端自己

所以部署时把三平台二进制丢进 `clients/` 即可：

```
/opt/sakura/clients/
├── sakura-linux-amd64
├── sakura-linux-arm64
└── sakura-windows-amd64.exe
```

构建脚本会在 `dist/clients/` 里生成这些文件（未压缩版，兼容性优先）。

## 服务端怎么生成这些脚本

`pkg/onetap/onetap.go`：

- `Params` 结构体描述 host/port/scheme/user/token/二进制名；
- `LinuxScript()` / `PowerShellScript()` 返回完整脚本文本（`fmt.Sprintf` 模板）；
- `LinuxCommand()` / `WindowsCommand()` / `DockerCommand()` 返回面板上展示的一行命令。

新增平台（比如 macOS 用同一份 bash 脚本、或加一个 launchd 分支）只改这一个文件。

## 安全说明

- token 就是密钥，链接泄漏等于密钥泄漏；面板里可随时「重置密钥」使旧链接失效；
- 脚本里不含任何管理员凭据；
- `/dl` 只允许字母数字点横线和下划线，防目录穿越。
